1Overview

The Brand Analytics (BA) module stores and queries Amazon's Search Term Report data — a dataset that reveals how often shoppers search for any given term, which products they click, and which products they ultimately buy. This data is the foundation of the Demand sub-scorer in Tier 1.

SQLite Index
Local indexed DB of Amazon search term frequency data
Fast Lookup
O(1) keyword lookup during Tier 1 scoring — no API latency
Explorer UI
Browse, filter, and export any search term from the dataset

2What is Brand Analytics Data

Amazon Brand Analytics is a report available to brand-registered sellers. The Search Term Report shows, for any given period (month/week), the top searched terms on Amazon along with:

  • How frequently each term was searched (Search Frequency Rank)
  • Which 3 ASINs received the most clicks for that term
  • The click share and conversion share for each of those ASINs
BA data is aggregated and anonymised by Amazon. It does not provide raw search volume numbers — instead it provides a rank (1 = most searched term in that period). The NPD Pipeline maps this rank to a demand score using a logarithmic scale.

Data coverage

The dataset covers the top ~600,000 most-searched terms on Amazon US. If a keyword is not in the dataset, it means either:

  • It is searched so infrequently it falls outside the top ~600k, or
  • The BA database has not been populated or is out of date

3Data Fields Explained

search_frequency_rankinteger Rank among all terms for that period. Rank 1 = most searched. Lower number = higher demand.

4Running Ingestion

BA data is fetched from Amazon's Selling Partner API (SP-API) and stored in a local SQLite file. You must run ingestion before using BA data in scoring.

Management command

# Inside the Docker container docker exec -it npd_web python manage.py ingest_brand_analytics # With specific date range docker exec -it npd_web python manage.py ingest_brand_analytics \ --start-date 2026-05-01 \ --end-date 2026-05-31 \ --period MONTH

Via the API

POST /api/brand-analytics/ingest/ { "start_date": "2026-05-01", "end_date": "2026-05-31", "report_period": "MONTH" } // Omit all fields to default to previous full calendar month

Ingestion result

FieldDescription
statussuccess or error
rows_insertedNumber of search term rows added to the SQLite index
report_dateThe period label stored (e.g. 2026-05)
duration_secondsTotal time for the ingestion run
completed_atISO timestamp of completion — visible in sidebar DB status
Ingestion requires valid SP-API credentials in your .env file: SPAPI_REFRESH_TOKEN, SPAPI_CLIENT_ID, SPAPI_CLIENT_SECRET, and SPAPI_MARKETPLACE_ID. Without these the ingestion will fail.

How often to refresh

Amazon publishes monthly BA reports on approximately the 15th of the following month. Run ingestion once per month after the new report is available. The scorer always uses the latest available period in the database.

5Using the BA Explorer

Navigate to Tools → BA Explorer to browse the indexed search term data interactively.

Search

Type any keyword to look it up. The result shows its Search Frequency Rank, click shares, conversion shares, and the top 3 clicked ASINs for the most recent period in the database.

Filters

  • Report Period — select a specific month if multiple periods are indexed
  • Min Rank / Max Rank — filter by demand tier (e.g. rank 1–10,000 = high demand)

What to look for

  • A low rank (e.g. 1,500) means the term is very commonly searched — strong demand.
  • A high click_share_1 (e.g. 0.65) means a single ASIN captures most clicks — indicates a dominant brand, which is a differentiation challenge.
  • Multiple ASINs with balanced click shares (e.g. 0.25 / 0.20 / 0.18) indicates a fragmented market — easier to enter.
Use the BA Explorer to manually validate a keyword before scoring it. If the rank is above 200,000, the demand is probably too low for a viable product — the economics scorer will likely penalise it.

6How BA Data Feeds Scoring

During Tier 1 scoring, the Demand sub-scorer queries the BA index for the keyword being scored. This is the primary use of BA data in the pipeline.

Tier 1 scoring flow for "bamboo travel mug": 1. BA lookup: search_frequency_rank = 4,521 2. Rank → Demand score: rank 4,521 → score 71 3. Weight applied: Demand × 35% = 24.85 contribution 4. Composite score: sum of all 5 weighted sub-scores

The Demand scorer formula

The rank is mapped to a 0–100 score using a logarithmic scale so that very high-demand terms (rank 1–1,000) get scores of 80–100, while mid-range terms (10k–100k) score in the 35–60 range.

# Simplified demand score formula import math def demand_score(rank): if rank is None: return 35 # rescaled when no BA data max_rank = 600_000 score = 100 * (1 - math.log(rank) / math.log(max_rank)) return max(0, min(100, round(score)))

BA data weight in composite score

Sub-scorerWeightBA data used?
Demand35%Yes — primary input
Saturation25%No — from SERP
Differentiation20%No — from SERP
Fit10%No — keyword rules
Economic Viability10%No — from product prices

7When No BA Data Exists

If a keyword is not found in the BA index, the scorer uses a rescaled demand score of 35 (below the mid-point) and adds the flag no_ba_data to the idea. The composite score is then recalculated with the remaining 65% of weight redistributed proportionally.

An idea scored with no_ba_data may have an artificially deflated or inflated demand component. Review the score carefully before promoting. Check the BA Explorer to verify whether the term exists under a slightly different spelling.

Checking for no_ba_data ideas

On the Dashboard or Task Board, the no ba data flag badge appears on any idea affected. You can also filter by this flag via the API:

GET /api/ideas/?flag=no_ba_data
