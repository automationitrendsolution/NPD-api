1Authentication & Base URL

All API endpoints are served under the /api/ prefix on the same host as the UI.

Base URL: http://localhost:8000/api/

CSRF Protection

All state-mutating requests (POST PATCH DELETE) require a valid CSRF token. The token is embedded in every HTML page:

<!-- In the page head --> <meta name="csrf-token" content="{{ csrf_token }}"> // In JavaScript const CSRF = document.querySelector('meta[name="csrf-token"]')?.content; fetch('/api/score/', { method: 'POST', headers: { 'Content-Type': 'application/json', 'X-CSRFToken': CSRF }, body: JSON.stringify({ keyword: 'bamboo mug' }) });

GET requests do not require CSRF.

2Ideas API

CRUD operations on the MongoDB ideas collection — the central data store of the pipeline.

GET /api/ideas/ — List ideas

Returns all ideas. Supports optional query filters:

ParamTypeDescription
status optionalstringnew / scored / shortlisted / pre_sourcing / approved / dismissed
source optionalstringhuman_seeded / autonomous / adjacency_mining
min_score optionalfloatOnly return ideas with tier1_score ≥ min_score
// All ideas GET /api/ideas/ // Scored ideas only GET /api/ideas/?status=scored // Ideas with score ≥ 55 GET /api/ideas/?min_score=55 // Response { "count": 42, "ideas": [ { "idea_id": "uuid...", "keyword": "bamboo mug", ... } ] }

GET /api/ideas/<idea_id>/ — Get one idea

GET /api/ideas/3f2a1b-uuid-here/ // Returns the full idea document { "idea_id": "3f2a1b-...", "keyword": "bamboo travel mug", "status": "scored", "tier1_score": 74, "tier1_scores": { "demand": 80, "saturation": 65, ... }, "flags": ["strong_demand"], "created_at": "2026-05-01T12:00:00Z", "updated_at": "2026-05-01T12:04:31Z" }

PATCH /api/ideas/<idea_id>/update/ — Update an idea

Update any field on an existing idea. Commonly used to change status (pipeline stage transitions).

PATCH /api/ideas/3f2a1b-uuid/update/ { "status": "shortlisted" }

DELETE /api/ideas/<idea_id>/delete/ — Delete an idea

DELETE /api/ideas/3f2a1b-uuid/delete/ // Returns 204 No Content on success
Deletion is permanent. The idea document and all scoring evidence are removed from MongoDB. Prefer setting status = "dismissed" to keep the record for the cooldown system.

3Scoring API

POST /api/score/ — Run Tier 1 scoring

Runs the full 12-step deterministic scoring pipeline for a keyword. This is the core action of the product.

POST /api/score/ { "keyword": "bamboo travel mug", required "concept": "eco-friendly mug", optional "source": "human_seeded", optional "force_rescore": false optional }

Response:

{ "status": "scored", // scored | dismissed | skipped | error "idea_id": "uuid...", "keyword": "bamboo travel mug", "tier1_score": 74, "tier1_scores": { "demand": 80, "saturation": 65, "differentiation": 70, "fit": 100, "economic_viability": 60 }, "flags": ["strong_demand"], "eligible_for_tier15": true, "duration_seconds": 12.4 }
source valueDescription
human_seededIdea originated from a human (default)
autonomousIdea discovered by the autonomous mining agent
adjacency_miningIdea discovered via keyword adjacency expansion

6LLM Analysis API

POST /api/analyse/ — Tier 2C LLM synthesis

Sends all collected evidence (SERP, products, reviews, BA data) to GPT-4o for a structured synthesis report.

POST /api/analyse/ { "idea_id": "uuid...", "force": false } // Response { "status": "complete", "idea_id": "uuid...", "keyword": "bamboo travel mug", "analysis": { "opportunity_summary": "Strong demand in eco kitchenware...", "key_differentiators": ["compostable packaging", "lifetime warranty"], "main_risks": ["high saturation from established brands"], "review_sentiment": "positive — customers love portability", "recommended_next_step": "proceed to pre-sourcing" }, "duration_seconds": 18.3 }
Requires status = "shortlisted" and completed review scraping (reviews_scraped = true). Uses OpenAI GPT-4o — requires OPENAI_API_KEY in .env.

POST /api/presource/ — Tier 3 pre-sourcing document

Generates a full pre-sourcing document: product concept, Amazon listing draft, and manufacturer spec.

POST /api/presource/ { "idea_id": "uuid...", "force": false } // Response { "status": "complete", "presourcing_data": { "product_concept": "A 16oz bamboo-fibre...", "listing_title": "Bamboo Travel Mug 16oz...", "bullet_points": ["...", "..."], "materials_spec": "70% bamboo fibre, 30% PP...", "supplier_search_terms": ["bamboo fiber travel mug manufacturer"], "lead_time_assumptions": "45–60 days from order..." }, "duration_seconds": 28.1 }

8System API

GET /api/db-status/ — MongoDB health check

Used by the sidebar to display the live database status indicator. Returns MongoDB connectivity and idea count.

GET /api/db-status/ // Connected { "connected": true, "db_name": "npd_db", "host": "localhost:27017", "ideas_count": 42 } // Disconnected { "connected": false, "error": "Connection refused" }

9Errors & Status Codes

HTTP CodeMeaningCommon cause
200OKRequest succeeded
400Bad RequestMissing required field, invalid value, or validation failure
403ForbiddenMissing or invalid CSRF token on POST/PATCH/DELETE
404Not Foundidea_id does not exist in the store
500Server ErrorScraper timeout, MongoDB unreachable, or unhandled exception
502Bad GatewaySP-API or OpenAI API returned an error during ingestion / LLM call

Error response format

All error responses return a JSON body with an error key:

{ "error": "'keyword' is required" }

Scraping errors

If a scraping request times out or Amazon returns an unexpected page structure, the API returns a 500 with the raw error message. Common causes:

  • ScrapingBee quota exhausted — check your dashboard
  • Amazon blocked the request — retry with a different keyword
  • HTML parser selector change — update api/search/parser.py or api/product/parser.py
